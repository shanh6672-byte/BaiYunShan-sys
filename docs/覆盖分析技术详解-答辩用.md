## 一、今日轨迹点怎么确定？

### 代码实现

```python
now = datetime.datetime.now(datetime.timezone.utc)

if period == 'today':
    start_time = now.replace(hour=0, minute=0, second=0, microsecond=0)
    # 即：今天 00:00:00 UTC → 当前时刻

pts = PatrolTrackPoint.query.filter(
    PatrolTrackPoint.timestamp >= start_time
).all()

# 也加入 RangerTrack / DroneTrack（两条轨迹表同步写入）
ranger_tracks = RangerTrack.query.filter(RangerTrack.timestamp >= start_time).all()
drone_tracks = DroneTrack.query.filter(DroneTrack.timestamp >= start_time).all()
```

### 为什么用三张表？

系统在轨迹模拟器中**同步写入**三张表：

| 表 | 用途 | 写入频率 |
|------|------|---------|
| `ranger_tracks` / `drone_tracks` | 实时位置（用来在地图上移动图标） | 每秒 1 条 |
| `patrol_track_points` | 历史轨迹查询（支持 session 分组） | 每秒 1 条，每 1500 秒换 session |

三张表都查是为了**覆盖全部轨迹数据**——即使某张表写入延迟，也不会遗漏。

### 答辩可以说的话

> "我们通过三张轨迹表联合查询今日所有巡护点。PatrolTrackPoint 专门为历史轨迹和覆盖分析设计，每条记录包含 entity_id（区分护林员/无人机）、经纬度、时间戳和 session_id。查询条件 `timestamp >= today 00:00:00` 就能获取今天全部巡护轨迹数据。"

## 二、500m 缓冲区怎么确定？

### 代码实现

```python
BUFFER_M = 500  # 米

for lng, lat in all_points:
    # 1度 ≈ 111320米（WGS84 球体近似）
    buf_deg = (BUFFER_M / 111320.0)  # 米 → 度
    p = Point(lng, lat)
    buffers.append(p.buffer(buf_deg))
```

### 为什么是 500m？

- 护林员在开阔林区可视范围约 **300m**，在山脊位置可达 **500m**
- 无人机在 120m 高度飞行时，相机视场覆盖约 **800m**
- 综合取 **500m** 作为平均有效巡护视线半径

### 答辩可以说的话

> "500 米缓冲区半径是综合考虑护林员地面视线范围（约 300m）和无人机高空巡查覆盖（约 800m）后取的折中值。每个轨迹点以 Point 为中心、500m 为半径生成一个圆形缓冲区，代表'这个位置可以被有效巡查到的区域'。"

## 三、缓冲区合并（union）为什么必要？

### 代码实现

```python
from shapely.ops import unary_union

# N 个点 → N 个圆形缓冲区 → 1 个合并多边形
covered_union = unary_union(buffers)
```

### 图示

```
合并前：                     合并后：
o  o   o    o              +----------+
 \/ \ /   /  /              |          |
  \/ \  /  /     →         |  覆盖区域  |
   \/ \/ /                  |          |
    \/ \/                   +----------+
     \/
   重叠部分只算一次
```

### 答辩可以说的话

> "单个轨迹点的缓冲区是彼此重叠的——相邻点之间距离通常只有几十米。如果不合并，重叠区域的面积会被重复计算，导致覆盖率虚高。Shapely 的 `unary_union` 函数将所有缓冲区合并为一个整体多边形，重叠部分只算一次面积，确保覆盖率计算准确。"

## 四、林场边界怎么确定？

### 代码实现

```python
def _fetch_forest_boundary():
    # 方案 A：从 GeoServer WFS 获取真实林场边界
    wfs_url = f'{GEOSERVER_URL}/baiyunshan/ows'
    params = {
        'service': 'WFS', 'version': '1.1.0', 'request': 'GetFeature',
        'typeName': 'baiyunshan:baiyunshan_compartments1',
        'outputFormat': 'application/json', 'srsName': 'EPSG:4326',
    }
    resp = requests.get(wfs_url, params=params, ...)
    geojson = resp.json()
    features = geojson.get('features', [])
    polygons = [shape(f['geometry']) for f in features]
    boundary = unary_union(polygons)  # 所有林班合并为一个整体边界
    return boundary, True

    # 方案 B（降级）：GeoServer 不可用时用近似边界框
    # return box(119.854, 28.480, 119.966, 28.581), False
```

### 为什么用 WFS 而不是硬编码 bbox？

- 硬编码 bbox 是矩形，无法反映林场实际不规则边界
- WFS 返回的 `baiyunshan_compartments1` 是 5 个林区的真实多边形
- `unary_union` 合并 5 个林区 = 完整林场边界

### 答辩可以说的话

> "林场边界不是我们拍脑袋画的矩形框，而是从 GeoServer WFS 服务实时获取的 5 个林班小班的真实多边形数据。Shapely 将其合并为一个整体边界多边形，确保覆盖率计算的是'在整个真实林场范围内'的覆盖比例。如果 GeoServer 网络不通，系统会降级使用近似边界框，保证功能可用。"

## 五、盲区怎么识别？

### 代码实现

```python
# 核心：林场边界 - 覆盖范围 = 盲区
blind_polygons = forest_bounds.difference(effective_coverage)

# 如果盲区由多个分离的多边形组成
if hasattr(blind_polygons, 'geoms'):
    # 按面积降序，取前 5 个最大的盲区
    geoms = sorted(list(blind_polygons.geoms), key=lambda g: g.area, reverse=True)[:5]
    for i, geom in enumerate(geoms):
        area = round(geom.area * DEG2_TO_MU, 0)
        if area < 50:  # 小于 50 亩的忽略
            continue
        centroid = geom.centroid
        blind_areas.append({
            'name': f'盲区{i+1}',
            'area': area,
            'lat': centroid.y,    # 盲区中心纬度
            'lng': centroid.x,    # 盲区中心经度
            'tag': '未覆盖' if area > 500 else '覆盖不足',
        })
```

### 图示

```
┌─────────────────────────────┐
│       林场边界               │
│   ┌──────────┐              │
│   │  覆盖区域 │    盲区 1     │
│   │          │   (850 亩)   │
│   └──────────┘              │
│                    盲区 2    │
│                    (320 亩)  │
│         盲区 3               │
│        (180 亩)              │
└─────────────────────────────┘
```

### 答辩可以说的话

> "盲区识别的核心是一个集合减法——林场边界减去有效覆盖范围，剩下就是没有被巡护到的区域。Shapely 的 `difference` 函数执行这个集合差运算。结果可能是一个或多个分离的多边形，我们按面积降序取前 5 个最大的作为'主要盲区'，并给出每个盲区的中心坐标和面积。面积大于 500 亩标记为'未覆盖'，50~500 亩标记为'覆盖不足'，小于 50 亩的碎片忽略不计。"

## 六、面积换算：度² → 亩

### 代码实现

```python
# 1 度 ≈ 111320 米（WGS84 赤道附近）
# 1 度² ≈ (111320)² = 12,392,142,400 平方米 = 12,392 平方公里
# 1 平方公里 = 1,500 亩
DEG2_TO_MU = (111320 ** 2) / 1_000_000 * 1500
# ≈ 18,579 亩/度²

total_area_mu = round(total_area_deg * DEG2_TO_MU, 0)
covered_area_mu = round(covered_area_deg * DEG2_TO_MU, 0)
```

### 答辩可以说的话

> "Shapely 计算出的面积单位是平方度。我们使用标准 WGS84 椭球近似——赤道附近 1 度约等于 111,320 米——将平方度转换为亩。这个换算在白云山所处纬度（约 N28.5°）误差小于 2%。"

## 七、完整度评价标准

```python
if coverage_rate >= 80:
    completeness = '优秀'
elif coverage_rate >= 60:
    completeness = '良好'
elif coverage_rate >= 40:
    completeness = '一般'
else:
    completeness = '较差'
```

### 标准来源

参考《森林防火条例》和林业巡护管理实践：
- **80%+** = 优秀：绝大部分林区被有效巡查
- **60~80%** = 良好：主要区域覆盖，存在少量盲区需关注
- **40~60%** = 一般：近半区域未被覆盖，需增派人手
- **< 40%** = 较差：巡护严重不足，需重新制定巡护计划

## 八、答辩核心要点一句话总结

| 环节 | 一句话 |
|------|--------|
| 轨迹数据 | 从两张实时轨迹表 + 一张历史轨迹表联合查询今日全部巡护点 |
| 缓冲区 | 每个轨迹点扩展 500m 视线范围，转换为 Shapely Point.buffer() |
| 合并去重 | unary_union 合并所有缓冲区，重叠区域面积只算一次 |
| 边界约束 | GeoServer WFS 获取 5 个林班真实多边形，合并为整体林场边界 |
| 覆盖率 | 覆盖面积 / 林场总面积 × 100%，度² → 亩换算 |
| 盲区识别 | 林场边界 - 覆盖范围 = 盲区，取前 5 个，< 50 亩的过滤 |
| 降级策略 | GeoServer 不可用时降级为近似边界框，保证功能不崩溃 |
