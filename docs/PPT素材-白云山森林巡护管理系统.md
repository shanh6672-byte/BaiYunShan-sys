## 01 项目概述

### 1.1 项目背景

白云山位于浙江省丽水市，林场总面积约 **1.2 万亩**，涵盖针叶林、阔叶林、混交林等多种林分类型，是区域生态安全的重要屏障。传统巡护模式依赖人工巡山、纸质记录和定期上报，面临三大痛点：

- **巡护效率低**：护林员单次巡护通常耗时 3-5 小时，覆盖范围有限，存在大片巡护盲区
- **信息传递滞后**：火情、虫害等灾害事件从发现到上报平均延迟 2-4 小时，错过最佳处置窗口
- **管理手段单一**：调度中心无法实时掌握护林员位置和任务执行情况，缺乏数据驱动的决策支持

### 1.2 建设意义

| 维度 | 传统模式 | 本系统 |
|------|---------|--------|
| 巡护监控 | 人工汇报，延迟 2h+ | SSE 实时推送，秒级更新 |
| 任务管理 | 纸质派发，无法追踪 | 在线发布→手机接受→轨迹跟踪 |
| 灾害响应 | 电话上报，定位不准 | GPS 定位 + 图片上传 + 一键派发 |
| 数据分析 | 经验判断 | GeoServer 遥感 + 缓冲区分析 |
| 覆盖评估 | 无法量化 | 实时覆盖率计算 + 盲区识别 |

## 02 项目设计与开发

### 2.1 开发过程

项目采用**敏捷迭代**模式，分五个阶段推进：

| 阶段 | 周期 | 核心产出 |
|------|------|---------|
| 需求分析 | 第 1 周 | 功能清单、数据需求、GeoServer 图层确认 |
| 原型搭建 | 第 2-3 周 | Flask 后端框架、数据库建模、底图加载 |
| 核心功能 | 第 4-6 周 | 驾驶舱、实时监控、任务管理、灾害上报 |
| 模块合并 | 第 7 周 | 整合组员巡护模块、路线联动、移动端适配 |
| 联调优化 | 第 8 周 | SSE 实时同步、UI 细节、覆盖率分析、Bug 修复 |

### 2.2 系统架构

```
前端: index.html + app.js + patrol-module.js + mobile.html
      Leaflet.js(地图) + ECharts(图表) + Turf.js(GIS分析)
         ↕ HTTP REST + SSE
后端: Flask + SQLAlchemy + Flask-JWT-Extended + Shapely
         ↕
数据: PostgreSQL(业务/轨迹) + GeoServer(WMS/WFS/WCS)
```

### 2.3 技术方案

| 层级 | 技术选型 | 选型理由 |
|------|---------|---------|
| 前端框架 | **原生 JavaScript** | 项目规模适中，减少学习曲线 |
| 地图引擎 | **Leaflet.js 1.9** | 轻量(42KB)、WMS/WFS原生支持 |
| 图表 | **ECharts 5.5** | 国产成熟方案，暗色主题适配 |
| 后端 | **Flask 3.x + gunicorn** | 轻量灵活，适合中小型API |
| 数据库 | **PostgreSQL 14** | 空间数据支持、JSON字段 |
| 认证 | **Flask-JWT-Extended** | 无状态Token，前后端分离 |
| 实时推送 | **Server-Sent Events** | 比WebSocket更轻量，浏览器原生 |
| 空间计算 | **Shapely** | Python几何运算标准库 |
| 地图服务 | **GeoServer 2.24** | 开源WMS/WFS/WCS服务器 |
| 部署 | **gunicorn + Render** | 免费PaaS，自动HTTPS |


## 03 系统实现

### 3.1 功能模块总览

- **综合驾驶舱**: 实时态势地图、在线统计、人员列表、灾害总览、实时警告
- **巡护监控与管理**: 实时监控(4护林员+6无人机)、覆盖分析(缓冲区+盲区)、任务管理(发布→完成)、路线规划(20条预设)、历史轨迹查询
- **空间数据分析**: 火情分析、NDVI分析(2021/2022)、FVC植被覆盖度
- **灾害识别处置**: 火情/虫害上报(含图片)、异常事件派发、SSE实时推送
- **移动端巡护**: 任务列表、路线显示、GPS巡护、拍照上报

### 3.2 核心业务流程

**任务-路线-模拟器-手机端四联动:**
桌面发布任务(选择路线+指派护林员) → 手机端接受 → 状态变为"进行中" → 模拟器切换路线 → 轨迹一致

**灾害上报-SSE实时推送:**
手机拍照上传 → 保存FireEvent → 同步GeoServer → SSE广播 → 全平台实时更新

### 3.3 巡护路线体系

共 **20条预设路线**，5个林区 × 4种模式:
- 边界巡护(矩形环绕) / 之字覆盖(全面扫描) / 主干道巡护(直线穿越) / 鱼骨巡护(主干+分支)
- 路线插值: Catmull-Rom样条平滑 / GPS漂移: ±3m高斯噪声

### 3.4 数据模型

| 表名 | 用途 | 关键字段 |
|------|------|---------|
| rangers | 护林员 | name, area, lat, lng, speed_kmh, status |
| drones | 无人机 | code, model, lat, lng, altitude_m, status |
| ranger_tracks | 实时轨迹 | ranger_id, lat, lng, speed_kmh, timestamp |
| patrol_track_points | 历史轨迹 | entity_id, session_id, lat, lng, timestamp |
| patrol_tasks | 巡护任务 | name, route_geometry, ranger_id, status |
| fire_events | 火情事件 | name, lat, lng, risk_level, area_mu, image_path |
| pest_events | 虫害事件 | name, lat, lng, disease_type, confidence |
| abnormal_events | 异常事件 | type, lat, lng, status |

### 4.2 典型应用场景

**场景一: 日常巡护调度**

## 05 总结与展望

### 5.1 完成情况

| 指标 | 目标 | 完成 |
|------|------|------|
| 核心模块 | 4个 | ✅ 全部完成 |
| API端点 | 30+ | ✅ 40+个 |
| 巡护路线 | 10条 | ✅ 20条(5区×4模式) |
| 数据模型 | 8张表 | ✅ 10+张表 |
| 实时推送 | SSE | ✅ 5类事件全覆盖 |
| 移动端 | 基础功能 | ✅ 任务+路线+拍照 |

### 5.2 技术亮点

1. **任务-路线-模拟器-手机端四联动**: 发布→接受→切换路线→轨迹一致
2. **SSE轻量级实时推送**: 比WebSocket更简单，浏览器原生支持
3. **Shapely缓冲区覆盖分析**: 500m视线缓冲 + unary_union合并 + 林场边界clip
4. **Catmull-Rom平滑路径**: 原始点插值 + GPS漂移 + 边界约束
5. **模块合并零冲突**: Blueprint + 独立JS模块无缝整合

### 5.3 不足与展望

| 不足 | 改进方向 |
|------|---------|
| DEM图层加载不稳定 | 本地瓦片缓存或COG方案 |
| 模拟轨迹非真实数据 | 接入手机GPS真实轨迹 |
| 移动端无原生App | UniApp/Flutter封装 |
| 无AI识别 | 接入YOLO/DeepLab自动检测 |
| 覆盖率用近似边界 | GeoServer WFS真实多边形 |
| 缺少测试 | pytest + Cypress E2E |

**未来方向**: AI智能识别 → 数字孪生3D可视化 → 大数据火灾预测 → 无人机自主巡护 → 多林场扩展
