### 白云山简介

白云山位于浙江省丽水市，属中亚热带季风气候区，地形以中低山为主，海拔 200~1500 米。林场总面积约 **1.2 万亩**，森林覆盖率超过 **85%**，涵盖针叶林、阔叶林、混交林、竹林等多种林分类型。

### 森林资源现状

- 浙江省森林覆盖率 **61.15%**，位居全国前列，森林资源丰富，生态保护任务繁重
- 白云山林场森林类型丰富、地形复杂、巡护范围广，森林资源保护压力较大
- 林场承担**森林防火、病虫害监测、资源巡查、生态保护**等多项职责
- 传统人工巡护模式下，单次巡护耗时 3~5 小时，全年累计巡护里程约 **8,000 公里**

## 第 7 页 · 技术选型

**建议布局：每个技术一个小卡片，关键在"为什么选它"**

### Leaflet.js —— 轻量级地图引擎
- 仅 42KB，比 OpenLayers（~500KB）轻一个数量级
- 插件生态丰富，原生支持 WMS/WFS 瓦片图层
- 学习成本低，适合本项目复杂度

### Flask —— 灵活的 Python Web 框架
- Python 生态最成熟的轻量 Web 框架
- 丰富的扩展（JWT/CORS/SQLAlchemy），按需组合
- 适合中小型 API 服务，开发效率高

### PostgreSQL + PostGIS —— 空间数据存储
- 开源关系型数据库标杆，PostGIS 提供空间数据类型
- 支持 GeoJSON 直接存取，与 GeoServer 无缝对接
- 成熟的 SQL 生态，复杂的统计查询轻松实现

### SSE —— 轻量级实时推送
- 比 WebSocket 更轻量，浏览器原生 EventSource API
- 单向推送（服务端→客户端），恰好匹配本系统实时更新场景
- 自动重连机制，无需额外库

### GeoServer —— 开源 GIS 服务器
- 支持 WMS/WFS/WCS 标准协议
- 可快速将 PostGIS 空间数据发布为 Web 地图服务
- 丰富的 SLD 样式配置，支持栅格和矢量图层

### Shapely —— Python 空间分析库
- 提供 buffer / union / intersection / difference 等几何运算
- 与 GeoJSON 无缝衔接，适合服务端空间计算

## 第 12 页 · 巡护覆盖分析（重点页）

> **最体现 GIS 分析能力的模块，建议重点讲解**

**业务需求：** 传统巡护无法判断是否真正覆盖整个林区——护林员走了，但到底覆盖了多少面积？哪里是盲区？

**设计思路：** 引入 GIS 缓冲区分析方法——将每个轨迹点扩展为 500m 视线范围缓冲区，所有缓冲区合并后与林场边界做叠加分析，计算覆盖率并识别盲区

**技术实现（流程图）：**

```
① 查询今日轨迹点
   PatrolTrackPoint.query.filter(timestamp >= today)
        ↓
② 为每个点创建 500m 缓冲区
   Point(lng, lat).buffer(500m) * N 个点
        ↓
③ 合并所有缓冲区（union）
   unary_union([buffer1, buffer2, ..., bufferN])
        ↓
④ 与林场边界相交（intersection）
   covered_union.intersection(forest_bounds)
        ↓
⑤ 计算覆盖率 + 差分识别盲区（difference）
   coverage_rate = covered_area / total_area * 100%
   blind_polygons = forest_bounds.difference(covered_union)
```

**技术栈：** Shapely（几何运算）+ Requests（WFS 获取边界）+ numpy（栅格统计）

**界面展示：** [覆盖分析结果截图——覆盖率 78.5% + 盲区列表]

**实现效果：** 覆盖率量化到百分比；盲区自动定位（经纬度 + 面积）；支持今日/近 7 天/近 30 天时间范围

## 第 13 页 · 巡护任务管理

**业务需求：** 管理员在线派发巡护任务，护林员手机接收执行，全过程可追踪

**设计思路：** 任务（Task）绑定路线（Route）+ 护林员（Ranger），状态流转驱动业务——草稿→待执行→进行中→已完成

**技术实现（核心联动机制）：**

```
管理员发布任务（选择路线 + 指定护林员）
    |  POST /api/patrol-tasks {route_name, route_waypoints, members}
    v
任务状态 = '待执行'
    |
    | 护林员手机端点击"接受任务"
    | PUT /api/patrol-tasks/<id> {status: '进行中'}
    v
模拟器 _get_task_route_for_ranger() 查找进行中任务
    |  读取 route_waypoints → RangerTrackGenerator(route=wps)
    v
护林员沿任务路线移动（鱼骨/之字/边界/主干道）
    |
    | 手机端 drawRouteAndMap() → 黄色虚线 = 规划路线
    v
任务完成 → 状态 = '已完成'，轨迹可回溯
```

**关键设计：** 发布什么路线，护林员就走什么路线——任务路线与模拟器路线全链路联动

**界面展示：** [任务列表 + 路线可视化截图]

**实现效果：** 20 条预设路线可选；手机端路线 = 桌面端分配路线；进度条实时更新

## 第 14 页 · 空间数据分析

**业务需求：** 林场需要定期评估植被健康状况，通过 NDVI/FVC 遥感指数监测植被年际变化

**设计思路：** GeoServer 已发布 2021/2022 年 NDVI 和 FVC 栅格数据（WMS + WCS），前端通过 WMS 加载可视化图层，后端通过 WCS 下载 GeoTIFF 做分区统计分析

**技术实现：**
- 图层加载：`L.tileLayer.wms()` → `baiyunshan:NDVI-21` / `baiyunshan:NDVI_1`
- 分区统计：WCS GetCoverage → GeoTIFF → numpy → 按林区 clip → 均值/分级面积
- 年份切换：选择年份 → 更新 WMS 图层 + 重新请求统计

**界面展示：** [NDVI 分析面板 + WMS 栅格图层截图]

**实现效果：** 2021/2022 年 NDVI 对比；林区级别统计（全部/按区）；WMS 栅格直接叠加到 Leaflet 地图

## 第 15 页 · 灾害识别与处置

**业务需求：** 护林员发现火情或虫害需要快速上报，指挥中心实时接收并派发处置任务

**设计思路：** 移动端拍照 → FormData 上传 → 后端保存 + 同步 GeoServer → SSE 实时广播 → 所有客户端同步更新

**技术实现（完整链路）：**

```
手机端拍照 + 填写信息（GPS自动填充坐标）
    |
    | FormData {image, name, lat, lng, riskLevel, ...}
    v
POST /api/disasters/upload
    |
    +-- 保存 FireEvent 到 PostgreSQL (id, name, lat, lng, area_mu, image_path...)
    +-- 图片存入 static/images/
    +-- 同步到 GeoServer 火情图层 (POST /api/geoserver/sync)
    +-- SSE broadcast 'fire_new' 事件
         |
         v
    所有在线客户端同时收到：
    +-- GeoServerLayers.addSingleFirePoint() → 地图新增标记
    +-- DisasterPanel.refreshFireList() → 侧栏列表更新
    +-- refreshDashboardStats() → 仪表盘火情数 +1
```

**界面展示：** [火情列表 + 详情弹窗（含照片/位置/风险等级/上报人/处置状态）]

**实现效果：** 上报到全平台可见延迟 < 1 秒（SSE）；火点数量与事件列表实时一致；详情弹窗展示完整信息

## 第 16 页 · 移动端巡护

**业务需求：** 护林员在野外需要通过手机查看任务、导航路线、上报灾害

**设计思路：** 移动端 Web 页面（mobile.html），复用主系统 API，JWT Token 认证，支持模拟 GPS 和真实 GPS 双模式

**技术实现：**
- 路线绘制：`extractWaypoints(task)` 兼容 `route_waypoints` 数组和 `routeGeometry` GeoJSON
- 巡护动画：`setInterval(500ms)` 沿 Catmull-Rom 插值路径逐步移动
- 拍照上报：`FormData` multipart 上传，复用主系统 `/api/disasters/upload`
- 坐标自动填充：拍照时自动附带当前巡护实时位置（lat/lng）

**界面展示：** [手机端三屏截图——任务列表 + 鱼骨路线 + 拍照上传]

**实现效果：** 黄色虚线 = 管理员分配的规划路线；绿色实线 = 护林员实际轨迹；拍照上报格式与主系统完全一致

## 第 17 页 · 综合风险评估（可选）

**业务需求：** 管理层需要综合评估林场当前风险状况，辅助调度决策

**设计思路：** 基于火情/虫害/异常事件/巡护覆盖四个维度，加权计算综合风险指数

**技术实现：**
- 火情风险：FireEvent 数量 × 风险等级权重
- 虫害风险：PestEvent 数量 × 置信度权重
- 异常风险：AbnormalEvent 未处理数量
- 覆盖风险：(1 - 覆盖率) × 权重
- 综合风险 = Σ(维度值 × 权重)

**界面展示：** [风险评估面板截图]

**实现效果：** 风险等级可视化（高/中/低 + 颜色标识）；各维度权重可配置

### 六大项目特色

| # | 特色 | 说明 |

| 4 | **GIS 空间分析** | Shapely 缓冲区/叠加分析量化巡护覆盖与盲区 |
| 5 | **巡护覆盖量化** | 将巡护质量从主观经验转为可计算的覆盖率 |
| 6 | **多端协同** | 桌面端 + 移动端数据实时同步，端到端闭环 |

### 五大创新点

| # | 创新点 | 具体实现 |
|---|--------|---------|
| 1 | **护林员 + 无人机协同巡护** | 10 个实体并行模拟，不同路线模式，统一监控 |
| 2 | **SSE 轻量级实时推送** | 比 WebSocket 简单，5 类事件全覆盖 |
| 3 | **缓冲区覆盖量化分析** | 500m 缓冲 + union + intersection + difference |
| 4 | **任务-路线-模拟器四联动** | 发布什么路线就走什么路线，全链路一致 |
| 5 | **模块化无冲突合并** | Blueprint + 独立 JS 模块，组员代码无缝整合 |

## 第 25 页 · 存在不足与改进方向

| 不足 | 改进方向 | 优先级 |
|------|---------|--------|
| DEM 高程图层加载不稳定 | 改用本地瓦片缓存或 Cloud Optimized GeoTIFF | 高 |
| 模拟轨迹为预设路线，非真实 GPS | 接入护林员手机 GPS 真实轨迹数据 | 高 |
| 移动端为 Web 页面，非原生 App | UniApp / Flutter 封装为跨平台应用 | 中 |
| 无 AI 自动识别能力 | 接入 YOLOv8 火情 / DeepLab 虫害识别 | 中 |
| 覆盖率计算使用近似边界框 | 接入 GeoServer WFS 真实林场多边形 | 中 |
| 缺少单元测试和 E2E 测试 | 引入 pytest + Cypress 测试框架 | 低 |
| 单服务器部署 | Docker + Nginx 负载均衡 | 低 |
